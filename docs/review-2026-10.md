# Codebase review, October 2026

Review of the MVP after a few months of inactivity, followed by a modernization pass.
Status of each finding is noted.

## Strengths

- Stage-oriented layout (`sources/`, `transcription/`, `summarize/`, `state/`) with a thin
  `pipeline.process` orchestrator and a `Source` protocol with two adapters.
- Resume key is the content hash; summaries keyed by `(content_hash, template_hash)`, so changing a
  template re-summarizes without re-transcribing (ADR 0002).
- Single `PodmaxxerError` hierarchy, wrapped at network boundaries, converted to clean CLI exits.
- Minimal, justified dependencies recorded as ADRs 0001-0008.

## Known limitations (tracked in beads)

- **No download-skipping.** The cache key is the content hash, computed after fetching, so URLs are
  re-downloaded every run. Needs a `source_uri` lookup (and ETag / Last-Modified) before fetch.
- **No real resume.** Stages are recorded only on completion; a crash mid-transcription leaves no
  trace. Needs per-stage status rows (started / failed / done).
- **Long transcripts** are sent in a single prompt and can exceed the model context window; needs
  chunked map-reduce summarization.
- **No retry/backoff** on summarization requests.
- **Sidecar heuristic** treats `episode.txt` beside `episode.mp3` as its transcript; `.srt` / `.vtt`
  cleaning is naive (no tag stripping).
- **`Source.fetch() -> Content`** yields exactly one item. RSS (last-N / newest) and YouTube need a
  multi-item shape, e.g. `list_items()` plus `fetch(item)`.
- **Prices and model names** in ADR 0008 are a point-in-time snapshot.

## Roadmap

1. `source_uri` cache and conditional requests.
2. Per-stage status for real resume.
3. Chunked summarization and retry/backoff.
4. Multi-item sources: RSS, then YouTube via `yt-dlp`.
5. Optional cloud transcription fallback if local quality or speed is insufficient.
